# chat_ui_builder 旧目录残留清理设计

## 需求详情
用户要求仅处理历史 agent 目录（已迁移）相关残留，包含：
1. 删除旧目录及残留文件（若存在）。
2. 删除仓库内所有指向旧目录的引用、旧启动说明与路径字符串。
3. 不修改已迁移到根目录 `chat_ui_builder/` 的新代码。
4. 不影响与 chat_ui_builder 无关功能。

## 澄清结果
- 本次只做“旧目录路径清理”，不进行功能重构。
- 若旧目录已不存在，则以“确认不存在 + 清理残留引用”作为完成标准。
- 历史文档中的旧目录说明统一更新为当前 `chat_ui_builder/` 路径表述。

## WHAT
- 扫描并确认旧 agent 目录状态。
- 全仓检索并清理旧目录路径字符串。
- 仅修改命中文档/计划文件与本次流程文件（设计、计划、进度）。

## WHY
- 旧目录已迁移，残留引用会误导后续开发与运维执行。
- 清理路径残留可降低启动失败、脚本执行失败与文档歧义风险。

## HOW
1. 使用 `rg` 定位旧目录路径引用。
2. 若旧目录存在则删除；不存在则记录核验结果。
3. 将历史文档里的旧目录引用替换为 `chat_ui_builder/` 对应路径。
4. 二次检索确认仓库中不再出现旧目录路径字符串。
5. 追加 `progress.md` 记录并提交。
